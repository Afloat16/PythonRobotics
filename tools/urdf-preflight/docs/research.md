# 调研与产品选择

日期：2026-09-30。完整来源编号见 [REFERENCES.md](../REFERENCES.md)。

## 结论

选择做 **URDF 文件级启动前检查器**，而不是再做一个运动规划框架、仿真器或可视化平台。它服务于已有机器人模型的导出、修改、提交和导入之前，输入一个文件就能获得可执行的排查建议。

这是一项基于生态与工作流的产品判断，不是用户规模调查结论；尚无真实用户留存、误报率或商业需求统计，也不声称所有机器人项目都需要 URDF。

## 调研路径

先看高关注度机器人项目的目标和使用入口，再检查专业 URDF 工具的能力边界；随后核对格式语义、动力学约束和 XML 安全接口，最后阅读真实 issue，区分静态检查能解决的问题与引擎内部问题。

| 项目 | 页面显示星标快照 | 已有能力 | 对本工具的设计影响 |
|---|---:|---|---|
| PythonRobotics [R5] | 约 30.6k | 教学与算法示例 | 小入口、可读代码、可运行示例 |
| MuJoCo [R6] | 约 15.4k | 物理与动力学仿真 | 检查非法物理参数，但不替代引擎测试 |
| Pinocchio [R7] | 约 3.8k | 刚体运动学/动力学 | 完整张量与正确模型语义的重要性 |
| MoveIt 2 [R8] | 约 2.0k | ROS 2 操作与规划框架 | 不要求先启动完整机器人软件栈 |
| robot_descriptions.py [R10] | 833 | 模型分发与加载便利层 | 显式 package 映射，避免隐式下载 |
| yourdfpy [R9] | 未记录 | 解析、验证、修改、可视化 | 承认已有 validation；定位为诊断与 CI 的补充 |
| urdf-loaders [R11] | 未记录 | Unity/Three.js 模型加载与显示 | 首版不重复做三维查看器 |

星标是本次访问网页的显示值，通常经过取整且会变化；表格不是实时榜单。专业工具即使星标较少，也比不相关的热门项目更值得作为功能对照。

## 为什么这个范围值得做

模型路径问题可以在导入前检查；引用不存在的 link、图中多父节点/闭环、错误限位和非法数值同样无需启动仿真。完整惯性张量具有可计算的约束 [R1,R2]。这些检查能够复用到不同的 URDF 下游工作流。

已有的 `check_urdf` 和 yourdfpy 已经覆盖部分结构/验证需求。本工具不以“没有人做过”为立项前提，而把以下组合做成一条简单工作流：**零运行时依赖、聚合诊断、源文件位置、修复建议、版本感知、可审阅基线、离线 HTML 和 CI 格式**。

阅读 MuJoCo 导入相关问题 [R12–R14] 后，明确排除了“保证模型在所有引擎中正确”的承诺。输入文件正确与具体加载器正确处理它是两件事。静态检查无法证明坐标系累加实现或导出器行为正确。

## 候选方向取舍

| 候选 | 优点 | 首版不选择的原因 |
|---|---|---|
| ROS 在线健康检查 | 能观测正在运行的系统 | ROS 版本、DDS、设备和网络环境使初次上手与验证成本较高 |
| 机器人数据集转换 | 训练与数据管理价值大 | 不同存储格式/时间戳/动作语义需要真实数据验证，易做成不完整的转换器 |
| URDF 三维查看器 | 展示直观 | 已有成熟工具；渲染与资源加载会扩大首版依赖 |
| URDF 静态体检 | 文件级入口、可离线测试、适合 CI | 范围清楚，可以输出可检查的局部结论；因此选择 |

以上是工程取舍，不是量化市场排名。

## 原创实现路径

从规范约束和自己构造的失效示例出发：先编写有来源的规则，再编写有位置的只读解析层；图检查使用非递归入度消减；惯性特征值使用归一化小矩阵 Jacobi 旋转，并额外与 NumPy 对照。报告模板与基线序列化独立实现。没有复制对照仓库的算法或改名打包其代码。

下一步维护最值得投入的是独立真实模型语料和误报标注、扩展字段的显式覆盖清单，以及不同 Python/操作系统组合的持续集成证据。首版不包含第三方机器人模型，避免把未经检查的资产许可证混入项目。
